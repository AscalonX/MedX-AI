# How MedX handles the five Track 2 questions

Research prototype. Synthetic data only. It supports clinicians; it does not diagnose, treat, prescribe or decide urgency. Spec of record: [docs/SPEC.md](../docs/SPEC.md).

| Track 2 question | Mechanism | Where it lives |
|---|---|---|
| **Incorrect or unsupported responses** | Every extracted field must carry a quote copied from the patient's text. Code (not the model) checks the quote exists; if not, the field is `unsupported`, shown in pencil style as "Needs check", never as fact. Output is schema-validated; patient text is treated as data; injection handling is not yet evaluated end to end. Measured as unsupported-claim rate with and without the verifier. Consult "consider" items come only from a fixed, curated rule list (51 rules over 12 presentations), are doctor-only, are labelled "not a diagnosis", and are dropped from the signed note unless the doctor keeps them. Consult lines that failed to save are marked "Not saved yet" and are never shown as part of the record; signing waits until they are saved. | `apps/web/lib/pipeline/verify.ts`, `schema.ts`, `prompts.ts`, `consult.ts`, `packages/shared/src/consultrules.json`; `docs/ai/DESIGN.md` §4, §6; `docs/ai/METRICS.md` M1 to M3, M5 |
| **Sensitive information** | Raw patient text is redacted (names, phone, ID, passport to tokens) before storage or any model call. Actor fields keep only known synthetic staff names; anything else typed there is redacted. Synthetic data only. API keys and database URLs come from environment variables, server-side only; `/api/health` never returns a credential (tested). The patient view is an explicit allowlist: no drug names, alerts, staff ids or notes. Consult listening uses the browser's cloud speech service and is enabled only after the clinician ticks the consent box (the consent is recorded as a line in the consult). | `apps/web/lib/pipeline/redact.ts`, `patientView.ts`, `config.ts`, `store.ts`; `CLAUDE.md` invariants 5 and 6 |
| **Uncertain results** | Per-field confidence shown as ink density. Provider error, schema error, unsupported language, or a required field below the threshold gives `abstained` and "needs human review" with a reason, never a guess. Missing is not negative: "no allergies" must be a patient quote. A shared-store failure answers 503 with "needs human review if it persists" rather than pretending a change was saved. Fault-injection tests require 100% abstain with zero asserted fields. | `apps/web/lib/pipeline/pipeline.ts`, `verify.ts`, `store.ts`; `docs/clinical/SPEC.md` §5; `docs/ai/DESIGN.md` §5; `docs/ai/METRICS.md` M5 |
| **High-risk decisions** | 18 deterministic, guideline-sourced red-flag rules run first on every patient turn and every consult line, before any model call; no model output can clear or downgrade a hit. A hit stops the intake with zero model calls, shows the patient a calm go-to-the-desk screen with no diagnosis, and interrupts the clinician screen with the highlighted sentence. A model safety screen runs in parallel and is add-only: its hits need a verified quote and appear as "Model-suggested, confirm". Blind holdout, rules alone: 7/10 emergencies caught (3/8 false alarms), which is why the screen exists. Vitals give a NEWS2-based triage level that is only a suggestion the nurse confirms. The AI never proposes drugs or doses. The doctor enters every order; deterministic checks (allergy, interaction, duplicate, pregnancy, dose range) require a written reason for high alerts, re-checked at submit, at pharmacist 1's verify, at dispense and at pickup. Options from the sourced alternatives table are re-checked against the patient and never written into an order. **Pharmacist 1** verifies or returns with a report; **pharmacist 2**, a different person, completes a six-item final check before dispensing (the server refuses the verifier); a new high alert on a dispensed, uncollected order sends it back to pharmacist 1. | `apps/web/lib/pipeline/redflags.ts`, `redFlagScreen.ts`, `vitals.ts`, `triage.ts`, `orders.ts`, `medrules.ts`; `packages/shared/src/redflags.json`, `medrules.json`; `docs/clinical/SPEC.md` §3, §7; `docs/clinical/PHARMACY-SPEC.md` §9, §10; `eval/results/holdout-rules-only.md` |
| **Human review** | Nothing is final until a clinician approves. Per field: approve, edit (old value kept, new value and reviewer), or take over. A red flag can be acknowledged or marked a false alarm with a reason, and stays visible. Every write names its actor: staff pick a synthetic identity in the "Who's signing in?" sheet before any write, and with `MEDX_STRICT_ROLES=1` the server refuses unknown actors and wrong roles (403). Every action (model, latency, inputs by reference, outputs, overrides, reviewer) goes to an append-only audit log, kept append-only across server instances. Each case has a trace of every rule check, model call and human decision with a deterministic replay digest. | `apps/web/app/api/sessions/[id]/review/route.ts`, `takeover/route.ts`; `apps/web/lib/pipeline/store.ts`, `trace.ts`; `packages/shared/src/staff.ts`; `docs/clinical/SPEC.md` §4 |

## What we do not claim
- Not clinically validated; not a medical device; synthetic cases only, small n.
- The verifier proves a quote exists, not that its meaning is right.
- The model screen will miss some cases and raise some false alarms; both are reported.
- The demo runs a mock model. Gemma-4-31B-IT on AMD-hosted models (AMD developer API) was evaluated on synthetic data only: field accuracy and latency thresholds were not met (eval/REPORT.md); the red-flag screen raised holdout recall from 7/10 to 9/10.
- Voice input uses the phone's or browser's cloud speech service, so audio leaves the app to that vendor. Clinic-side consult listening does too.
- The demo has no real login: reviewer identity is self-declared, so the two-person dispense check is procedural, not authenticated. The dispense checklist records what pharmacist 2 attests; there is no barcode or stock check.
- Redaction is pattern-based and imperfect.
- Triage is an adult NEWS2 suggestion (not pregnancy). Prescribing checks use a small rule set (59 drugs, 18 interactions, adult dose ceilings for 31) and miss what it lacks.
- Consider items come from a fixed 12-presentation list, not a complete differential.
