# W19 Patient mobile: medicine pickup status on the patient phone

STATUS: done. Not committed (the orchestrator handles git). Mobile tsc, eslint and `expo lint` are clean. `scripts/build-patient-web.sh` re-ran and refreshed `/patient` (apps/web/public/patient). An end-to-end browser check of the exported bundle passed 36/36.

## SUMMARY
The patient phone now follows the visit past nurse review, through the two pharmacist stages, up to medicine collection:
- **preparing**: hero reads "Your prescription is being prepared." A Pharmacy card says the pharmacy team is checking and preparing the medicine, and that this screen will say when it is ready.
- **ready**: hero reads "Your medicine is ready." A teal-tint card (teal border, no red) shows "Counter" with the number in 52 px type, then "Please go to pharmacy counter 2 and show code B-042." at title size. Without a counter it says "Please go to the pharmacy counter and show code B-042."
- **collected**: hero reads "You have collected your medicine." The card says: "If you have a question about your medicine, ask the pharmacist before you leave."
- The live timeline gains two steps: "Preparing your medicine" (active, then done) and "Ready to collect" (pending, then active), which turns into "Medicine collected" (done). Times show when this phone first saw each step, because the patient view has no timestamps.
- All new strings exist in th, it and en (Italian uses Lei, Thai has no particles, no emoji). The phone never shows drug names, pharmacist ids, notes or times.

## Changes
- `apps/mobile/src/api.ts`
  - Adds `PickupStatus` and `PatientPickup` (`{ status: "preparing" | "ready" | "collected"; counter?: string } | null`).
  - Adds `PatientView.pickup`.
  - `toPatient()` now whitelists pickup: a known status plus a trimmed counter of at most 40 characters, nothing else. A missing or unknown value becomes `null`, so older servers and older stored copies still work.
  - Adds `pickupPending()`.
- `apps/mobile/src/app/done.tsx`
  - **Polling (the key fix):** before this change, polling stopped as soon as the status was `approved`/`taken_over`, which is long before the doctor prescribes. Now one 4 s single-flight poll runs until `pickup.status === "collected"` and then stops.
  - `reviewedAt` is now set only once (`v ?? now`), because polling continues after review.
  - When pickup turns ready, the phone does three things once each: a Success haptic, a screen-reader announcement (the code is spelled out), and reading it aloud if the patient turned on "Read questions aloud".
  - Pickup card and the extra steps are added.
  - A non-breaking hyphen (U+2011) keeps the code from wrapping as "B-" / "042" in the ready sentence.
  - The needs-human card and the "A nurse will call you" note are hidden once a prescription exists.
- `apps/mobile/src/app/index.tsx`: the visit language stays locked on Home while medicine is preparing or ready.
- `apps/mobile/src/i18n.ts`: 11 new keys per language (pickupEyebrow, pickupPreparingTitle/Body, pickupReadyTitle, pickupReadyBody(code, counter?), pickupCounter, pickupCollectedTitle/Body, stepPreparing, stepReady, stepCollected).

## ASSUMPTIONS
- The counter is a short label set by the pharmacist (for example "2"). Up to 4 characters it is shown in 52 px type; longer labels use title size. It goes through `friendly()` in case the server redacted part of it.
- If a prescription exists, the "Reviewed" step counts as done even when the intake status is still `awaiting_review`, because a clinician has seen the patient. Its time is shown only when the status really is approved or taken over.
- Polling keeps its 4 s interval after review, so the patient sees "ready" within about 4 s of the pharmacist's call. Each poll is one small GET while the Done screen is open.

## RISKS
- U+2011 is not in the SCBXBeta2 font (checked with fontTools). The browser draws that one glyph from a fallback font, so the hyphen in the ready sentence looks slightly lighter than the hero code. This was accepted in exchange for the code never splitting.
- An escalated patient stays on the red-flag screen, which does not poll, so the pickup status never shows on their phone. Staff call them in person. This is by design: the red-flag screen has no patient exit.
- "New intake" (+) and "Start" on Home still clear the stored session even while medicine is pending. This is the existing behaviour for approved sessions and is kept for the demo, where staff reuse one phone.
- Native iOS/Android were not run in this wave. The same code ran on the web export. Haptics and speech cannot be observed on headless web.
- During `git diff`, git warned that `apps/mobile/src/api.ts` and `index.tsx` will be normalised from CRLF to LF (the new `.gitattributes eol=lf`). The working files have no CR bytes. This is line-ending normalisation, owned by the w19 CRLF task.
- `apps/web/public/patient/assets/node_modules/expo-router/assets/*.png` is produced by the export but ignored by the root `.gitignore` (`node_modules/`). This was already the case before this wave (those PNGs were never tracked). They are only used by expo-router's error and sitemap screens.
